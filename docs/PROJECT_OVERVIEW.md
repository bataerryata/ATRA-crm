# نمای کلی پروژه ATRA

## هدف
ATRA سامانه CRM و مدیریت عملیات فروش برای شرکت قلب صنعت جهان (WIHCo) و برند باتری آتا است. هدف، نرم‌افزار عملیاتی قابل اتکا برای استفاده روزانه کارکنان است؛ نه داشبورد نمایشی.

## اصول محصول
- زبان فارسی و رابط راست‌چین (RTL)
- تقویم شمسی و ارقام لاتین
- واحد پول تومان
- واکنش‌گرا برای Windows و Android و قابل توسعه به PWA
- طراحی صنعتی، حرفه‌ای و منسجم
- هزینه پایین و قابل پیش‌بینی
- حفظ طراحی تأییدشده فعلی؛ تغییر بصری گسترده بدون تأیید مالک ممنوع است.

## معماری هدف
- Frontend: React + TypeScript + TanStack Start (وضعیت انطباق نسخه موجود باید با کد بررسی شود)
- Database: Supabase / PostgreSQL، مشروط به تأیید وضعیت اتصال و ساختار فعلی
- Authentication: Supabase Auth با رابط ورود اختصاصی، مشروط به بررسی پیاده‌سازی فعلی
- Version control: GitHub؛ مرجع اصلی کد
- Design: Figma؛ مرجع طراحی تأییدشده
- Automation: n8n در مراحل بعدی، در صورت نیاز
- AI: معماری مستقل از ارائه‌دهنده مدل

## مراجع حقیقت
- کد و تاریخچه تغییرات: GitHub
- طراحی تأییدشده: Figma
- داده‌های عملیاتی: Supabase، در صورت تأیید اتصال واقعی
- حسابداری: نرم‌افزار محک؛ ATRA نباید بی‌دلیل جایگزین آن شود. هر اتصال آتی به محک در ابتدا فقط خواندنی است.

## ماژول‌های دامنه
داشبورد و گزارش‌ها؛ مشتریان و سوابق؛ محصولات و مدل‌های باتری؛ فرصت‌ها و پیش‌فاکتورها؛ قیمت‌گذاری؛ سفارش‌ها؛ آماده‌سازی و مونتاژ؛ کنترل کیفیت؛ تحویل؛ وظایف و پیگیری‌ها؛ شکایات و گارانتی؛ نمایش خواندنی وضعیت مطالبات؛ عملکرد فروش؛ کاربران و مجوزها؛ دستیار هوشمند؛ تنظیمات، ورود/خروجی و پشتیبان‌گیری.

## قواعد همکاری و توسعه
1. پیش از تغییر، کد، مستندات و طراحی موجود بررسی شود.
2. قابلیت قابل مشاهده در UI لزوماً عملیاتی نیست؛ اتصال به داده و رفتار واقعی باید اثبات شود.
3. تغییرات کوچک، قابل بازبینی و برگشت‌پذیر باشند.
4. از Branch و Pull Request استفاده شود؛ تغییر مستقیم و گسترده روی main انجام نشود.
5. تست و Build باید واقعاً اجرا و نتیجه گزارش شود.
6. هیچ داده‌ای بدون مجوز حذف نشود؛ Migration مخرب، انتقال داده، انتشار یا فعال‌سازی سرویس پولی نیازمند تأیید مالک است.
7. مجوزها در سرور و دیتابیس اعمال شوند؛ مخفی‌کردن دکمه در UI کنترل امنیتی محسوب نمی‌شود.
8. کلیدهای محرمانه در کد Frontend یا مخزن قرار نگیرند.
9. دستیار AI فقط به داده‌های مجاز کاربر دسترسی داشته باشد و بدون درخواست و تأیید صریح اقدام نکند.
10. هر تصمیم تأییدشده در مستندات ثبت و تصمیم‌های پیشنهادی از تصمیم‌های قطعی جدا شوند.

## وضعیت
این سند چارچوب پروژه را ثبت می‌کند. وضعیت واقعی هر ماژول و فناوری باید با Audit کد و سرویس‌های متصل تکمیل شود؛ این سند به‌تنهایی اثبات‌کننده پیاده‌سازی هیچ قابلیتی نیست.
