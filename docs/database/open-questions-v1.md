# تصمیم‌های باز پیش از طراحی SQL نهایی ATRA

این فهرست عمداً کوتاه و متمرکز بر مواردی است که بر مدل داده، محاسبات مالی یا امنیت اثر مستقیم دارند. تا پاسخ مالک، هیچ‌کدام نباید با حدس پیاده‌سازی شوند.

| اولویت | موضوع | وضعیت فعلی | تصمیم موردنیاز |
|---|---|---|---|
| حیاتی | استخر پورسانت تیمی | نرخ مدیر فروش ۵۰۰ ریال/۵۰ تومان به‌ازای Ah و شرط تحقق تارگت مشخص است؛ فرمول استخر نامشخص | استخر از چه مبنایی تأمین می‌شود و سهم فروشنده/مدیر چگونه با هم جمع یا کسر می‌شوند؟ |
| بالا | تعارض قواعد تخفیف | تخفیف بر اساس محصول، مشتری/نوع مشتری، فروشنده و معامله خاص قابل تعریف است | در صورت چند قانون هم‌زمان، کدام اولویت دارد یا آیا کمترین سقف اعمال می‌شود؟ |
| بالا | حساب‌های نقدی و بانکی | ثبت مالی عملیاتی لازم است؛ مدیریت صندوق/حساب و انتقال بین آن‌ها هنوز پاسخ روشن ندارد | ATRA دفتر صندوق/بانک و انتقال داخلی را هم مدیریت کند یا فقط دریافت/پرداخت و مانده؟ |
| بالا | اتصال محک | بهای تمام‌شده از حسابداری دریافت شود و امکان اصلاح مجاز دستی وجود داشته باشد | نسخه نرم‌افزار، نوع خروجی/API، جهت تبادل و مرجع نهایی هر فیلد |
| بالا | محرمانگی شناخت مشتری | پرونده شناخت تجاری تأیید شده؛ باید حرفه‌ای و مستند باشد | کدام نقش‌ها یادداشت‌های محرمانه را می‌بینند/ویرایش می‌کنند؟ |
| متوسط | آرشیو و نگهداری اسناد | تاریخچه مهم باید حفظ شود | دوره نگهداری، سیاست آرشیو، حذف قانونی و مالکیت فایل |
| متوسط | قراردادها | به‌عنوان قابلیت پیشنهادی مطرح شده، نه تصمیم نهایی | آیا مدیریت قراردادها جزو دامنه نسخه اول است؟ |
| متوسط | Excel و ورود داده | پیشنهاد شده | کدام داده‌ها و از چه منابعی باید وارد شوند؟ |
| متوسط | نقش‌های پایه | نقش‌ها و مجوزهای پویا تأیید شده‌اند | فهرست اولیه نقش‌ها و ماتریس دسترسی هرکدام |
| متوسط | مدل محصول و Ah | مدل و Ah توسط مدیر قابل تعریف است | اگر چند Ah برای هر مدل مجاز باشد، ساختار کاتالوگ نهایی چیست؟ |
| متوسط | تقویم | رویداد عمومی/محرمانه و تقویم شخصی/سازمانی تأیید شده | چه نقش‌هایی می‌توانند رویداد محرمانه بسازند و چه کسی را دعوت کنند؟ |

## تصمیم‌های آگاهانه برای فاز بعد
- تا روشن‌شدن استخر پورسانت، فقط accrualهای فروشنده و محاسبه جداگانه مدیر را طراحی مفهومی می‌کنیم؛ هیچ پرداخت نهایی خودکار نمی‌شود.
- تا تعیین اولویت تخفیف، قواعد را نسخه‌دار ذخیره می‌کنیم ولی resolver نهایی را قطعی نمی‌کنیم.
- تا دریافت مستندات محک، هیچ اتصال یا mapping قطعی ساخته نمی‌شود.
- برای شناخت مشتری، داده خصوصی/حساس نامرتبط با فروش جمع‌آوری نمی‌شود.
- قراردادها و Excel تا تأیید دامنه، قابلیت پیشنهادی باقی می‌مانند.
